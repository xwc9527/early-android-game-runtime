# Offline AOT generalization: route evidence

Result: `AOT_GENERALIZATION_EVIDENCE_SUFFICIENT` for the bounded two-game, one-ELF-per-game offline execution evidence required before final route comparison. This is evidence for advancing the AOT candidate to that comparison. It does not select AOT as primary, change D011 or Runtime ownership, or establish full APK playability. All execution claims below use original, locked ARMv7 game ELF bytes. The execution traces are comparison oracles; they are not translation inputs.

## Input, artifact, and execution identity

`prepare_apk_offline.py` selects the highest available 32-bit ARM ABI (`armeabi-v7a`, then `armeabi`), extracts every `.so` in that ABI, and calls `translate_offline.py` with the same `all-exidx`, relocatable, no-diagnostic policy. The translator reads ELF32 ARM executable code, dynamic symbols, init/fini entries, and EHABI exidx, then discovers direct CFG edges. It does not read a dynamic trace, package name, game name, or manually selected PC. The formal linker supplies load bias at runtime and binds the generated artifact by the original ELF identity.

The original APK preparation output is under `run-36408196579/`, including both APKs, selected ELF bytes, generated C, translation manifests, logs, and the original CI ZIP. Its `preparation.json` files establish:

| APK | Selected ELF | ELF bytes | Executable bytes | Fast blocks | Generated C bytes | Offline preparation |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Gloomy Dungeons 2 | `lib/armeabi-v7a/librenderer.so` | 9,376 | 4,114 | 308 | 136,626 | 0.129 s total APK preparation |
| KungFoo Barracuda | `lib/armeabi-v7a/libKungFooBarracudaNativeActivity.so` | 882,136 | 542,032 | 33,548 | 17,041,778 | 4.111 s total APK preparation |

The generated C is 33.2 and 31.4 times the executable bytes, respectively. This two-point range shows no obvious superlinear preparation growth; it does not establish library-wide scaling. The measured KungFoo object has 5,404,896 ARM64 `__text` bytes and took 82.40 s to compile in `run-36405016519/`. These are substantial packaging and build costs to carry into route comparison.

The exact no-diagnostic Gloomy C artifact generated by that APK preparation run, SHA-256 `9c1b6948cb5d8570066b6b01510a524e98927f3cf5bfdda627dbc02af003e397`, was compiled without retranslation and executed in `run-36417253721/` at formal linker biases `0x02800000` and `0x00010000`. Both 174-instruction interpreter/AOT differentials passed: 153 AOT, 21 SVC, zero ordinary fallback, 32 matching checkpoints, equal host calls and observables. The raw archive has the input ELF, exact generated C, manifest, compiler output, runtime traces, and both differential results. Its AOT object has 44,412 ARM64 `__text` bytes and took 0.49 s to compile.

The same offline policy ran both games' bounded ARM paths, with source and generated artifact hashes checked against each run's manifest. Gloomy used two distinct formal linker load biases in `run-36407011220/` and the exact APK-prepared artifact run above; KungFoo's larger path used runtime ELF identity binding in `run-36405016519/`. The original ZIP and extracted raw files are committed with each run. The KungFoo APK-preparation C and its execution-run C have different generated hashes because the former omits diagnostic tables; both use the same ELF and public fast-block policy. Direct execution of the former exact C is not claimed.

## Runtime-discovered path and fallbacks

KungFoo's `run-36405016519/differential.json` records 29,703 interpreter-oracle instructions, 26,404 AOT instructions, 3,299 interpreter instructions, 6,632 matching fast-block checkpoints, matching host calls and checked observables, and complete fallback accounting. The 125-instruction path beyond the earlier loader prefix had 117 AOT and eight SVC instructions, with no ordinary fallback. Translation finished before the interpreter trace was captured. This proves that the tested new path was not replayed from its own known trace.

The 3,299 interpreter instructions comprise 629 IT-state, 2,006 lookup-miss, and 664 SVC instructions. `run-36405016519/fallback-classification.json` classifies the 2,006 lookup-miss events: 1,520 are static-discovery gaps that a trace-independent executable-section sweep can decode; 192 occur at four indirect targets whose mode/address the current sweep misses; 294 are LDREX/STREX. These are public ARM discovery, mode, and atomic capability categories. No game identity or PC-specific translator exception was added. The current fallback share is 11.1% of this path, so the interpreter is not its main executor. One new workload cannot prove that fallback share converges across a game library.

The sweep experiment already exists in `run-36377799477/`: it reduced lookup misses to 1,232 but grew generated C to 25.41 MB, ARM64 `__text` to 7.99 MB, and retained a 0.453 guest-engine speed ratio. `all-exidx` is therefore the smaller tested policy; the sweep is evidence of a coverage/size tradeoff, not a reason to add game-specific blocks.

## Correctness and execution cost

Gloomy's relocatable runs `run-36407011220/` and `run-36404893556/` cover two linker placements, matching interpreter/AOT states, host calls, observables, and output. Its long warm run `run-36416574039/` repeated both renderer functions 16,384 times per process in five paired processes. Each pair has matching observables and host logs, complete instruction accounting, zero ordinary AOT fallback, 2,506,752 AOT and 344,064 SVC instructions. The guest-engine median is 60.137 ms for interpreter and 45.026 ms for AOT, a 1.336 ratio. The 256-iteration predecessor `run-36409452946/` had roughly 1 ms per sample and large timing spread, so it is not used for a performance conclusion.

KungFoo's bounded loader/onCreate path in `run-36405016519/` has seven paired guest-engine medians of 0.510 ms interpreter and 1.041 ms AOT, a 0.490 ratio. The short measurement is noisy, but all tested larger offline KungFoo variants were slower, including dense indexing and `-Os` (`run-36399573114/`, `run-36401174157/`). This refutes a performance advantage for the current generalized KungFoo artifact and measured path, not the AOT route itself. Boundary time is reported separately in the raw stage results; the guest-engine comparison excludes it.

Concurrent multi-ELF artifact binding, threads, callbacks, and a large game library are not exercised by these two one-ELF APKs. The current compiled backend holds one relocatable artifact/bias; APK preparation can generate every library, but runtime selection among several artifacts is not yet proved. These limits prohibit extrapolating this result to complete games or declaring AOT primary. They do not contradict the tested offline generalization claim.
