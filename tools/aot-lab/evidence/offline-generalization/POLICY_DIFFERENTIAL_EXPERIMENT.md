# EHABI entry-policy execution differential

The `all-exidx-sweep` fast-only artifact ran the new KungFoo path correctly, but its 25.41 MB generated C and 7.99 MB ARM64 `__text` still produced a 0.453 guest-engine speed ratio against the interpreter. The static `all-exidx` policy omits the broad executable-section sweep while retaining ELF symbols, init/fini entries, EHABI function starts, and direct control-flow discovery. Local preparation of the same 882,136-byte ELF produced 16.38 MB of fast-only C instead of 25.41 MB. A static replay is insufficient to decide actual dynamic coverage or performance.

This run generates the `all-exidx` artifact before collecting the real interpreter trace, then executes the bounded pre-thread-creation path. It records an in-run loader-prefix counter snapshot so the new path's AOT/fallback coverage is calculated using the same artifact, and captures fast-block PC/CPSR/register checkpoints against the interpreter oracle. Seven paired iOS ARM64 simulator samples test whether the smaller code improves guest-engine cost. This changes only a public ELF entry-discovery policy; no game identity, known PC, or observed trace enters translation.

The artifact has 33,548 fast blocks, 16,380,180 generated C bytes, 4,953,432 ARM64 `__text` bytes, and a 66.84-second compiler wall time.

The 29,703-instruction bounded execution passed the checked fast-block states, host calls, observables, and complete instruction/fallback accounting. AOT executed 26,404 instructions; interpreter executed 3,299, including 629 IT-state, 2,006 lookup-miss, and 664 SVC instructions. The 125-instruction new path retained 117 AOT and 8 SVC instructions, with no new ordinary fallback. Seven paired guest-engine measurements gave median interpreter 0.487 ms and AOT route 1.340 ms, a 0.363 speed ratio. The smaller static entry policy therefore preserves this path's correctness and coverage but does not solve the current fast-only artifact's performance regression. This is a result for this implementation and bounded workload, not a route-level impossibility proof.
